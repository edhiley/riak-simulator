# Design rules

These rules exist so the page looks like a deliberate instrument, not a generated template. They are enforced where possible: `npm run lint:design` fails on raw values, and `npm run build` runs it.

## Principles

1. **The cluster is the page.** The node cards, their partition tiles and the messages between them get the space. The controls, the header and the panels are a quiet frame round them. On a wide window the page fits the window and does not scroll. If a panel competes with the cluster for attention, the panel is wrong.
2. **Everything drawn is something the core did.** A pulse is a message, a dot is a saved copy, a working character is a step in the store. Nothing moves for decoration, and nothing animates unless the simulation changed.
3. **Strong hue means node.** Node colours are the only saturated, solid colours in the cluster drawing. The chrome comes from Material 3's Tonal Spot scheme from a violet seed, a hue no node uses. Controls use its soft container tints: writes tertiary, reads secondary, deletes error, pings primary. Two exceptions, each kept in its own frame: the pixel characters, which use the fixed `--pix-*` palette on a paper stage, and the site icon.
4. **Show the why.** Each step says what happened and why Riak does it that way: "What happened?", the "Why?" of each character, and the explainers. Text that only names a thing is not enough.
5. **Material 3 as a specification.** Colour roles, type scale, shape scale, state layers and motion tokens follow Material 3 exactly. We build our own small set of components to that spec; we do not use a component library. Icons come from Lucide, pinned, and every icon button has a label or a tooltip.
6. **Data looks like data.** Hashes, partition numbers, ports, vclocks, commands and replies are set in Roboto Mono. Numbers that change use tabular figures.
7. **Dense and calm.** Small type, tight spacing on the 4px grid, few borders.

## Tokens

All values live in `src/styles/tokens.css`, generated by `scripts/make-tokens.ts` (`npm run tokens`). Change the script, never the CSS.

| Group | Tokens | Source |
|---|---|---|
| Colour | `--md-sys-color-*` | Material 3 Tonal Spot scheme from seed `#6750a4`, light and dark |
| Pixel colour | `--pix-*` | Fixed palette for the pixel characters, the same in both themes |
| Node colour | `--node-0` … `--node-7`, `--node-N-on` for text on it | Okabe–Ito palette; its black is light grey in dark mode |
| Type | `--type-*`, `--font-plain`, `--font-mono` | Material 3 type scale; Roboto Flex and Roboto Mono, bundled |
| Shape | `--shape-*` | Material 3 corner scale |
| Space | `--space-1` … `--space-12` | 4px grid |
| Size | `--size-*`, `--stroke-*` | Fixed set |
| State | `--state-*`, `--dim` | Material 3 state-layer opacities |
| Motion | `--motion-*`, `--duration-*` | Material 3 easing and durations |

The cluster is capped at 8 nodes because there are 8 node colours. Each node card carries its name, and each tile its partition number, so colour is never the only cue.

Two files have fixed colours and are outside the lint: `public/favicon.svg`, which cannot read the page's tokens, and the sprites from `scripts/draw-characters.py`, which use `--pix-*`.

## Banned

The lint catches the first group; review catches the rest.

**Enforced by `lint:design`** (outside `tokens.css`):

- Raw colours: hex, `rgb()`, `hsl()`, named colours in style declarations.
- Pixel values. Use a space, size or stroke token. Geometry inside SVG drawing code is unitless and allowed.
- `font-family` and `font:` declarations other than `font: var(--type-…)`.
- Gradients, `box-shadow`, `backdrop-filter`, `filter: blur`.
- Emoji.

**Checked in review:**

- No hero banner, tagline block or marketing copy. The page opens on a working cluster.
- No cards inside cards. A pane is a surface container with no border; inside it, group with space, not boxes.
- No icon-in-a-coloured-circle tiles, no badges for decoration.
- No accent colour outside the Tonal Spot scheme. No glow, no glass.
- No centred body text. Text is left-aligned, sentence case, plain words.
- No loading spinners for things that take under 100 ms.

## Components

Built in `src/components/`, each to its Material 3 specification:

| Component | Material 3 reference | Notes |
|---|---|---|
| Button | Filled, tonal and text buttons | 40px target, full corner |
| Icon button | Standard icon button | Hide the controls, Play, Settings, theme, source code |
| Segmented button | Segmented button | Speed, node count, ring size, quorums, timing |
| Tabs | Primary tabs | The left column: Requests, Traffic, Data, Scenarios |
| Dialog | Basic dialog | The explainers, with an optional figure and links |
| Text field | Outlined text field | The console input is a multi-line variant in mono |
| Top app bar | Small top app bar | Product name from `src/lib/brand.ts` only |

State layers (hover, focus, pressed) use `--state-*` over the content colour. Focus is always visible: a `--stroke-focus` outline in `--md-sys-color-primary` (on node-coloured fills, `--md-sys-color-on-surface`).

## Motion

- **Simulation time** (messages travelling, replicas changing): linear, driven by the frame loop from simulation time. Never eased, because easing would misrepresent latency.
- **Interface chrome** (panes, state changes, tiles moving to a new card after a change of size): Material 3 standard or emphasised easing, `--duration-*` tokens.
- Respect `prefers-reduced-motion`: chrome transitions and animations drop to zero. Simulation playback stays, because it is the content; Pause and the speed control slow or stop it.

## Writing

All text on the page, the explainers and step texts included, is in simplified technical English, based on ASD-STE100:

- One idea per sentence. Most sentences are under 20 words.
- Active voice. Instructions are imperatives: "Run the command."
- Technical terms are used exactly and the same way each time: partition, vnode, node, replica, hash, preflist, coordinator. Explain a term once, then use it.
- State facts about the system. Do not describe what the user will feel or notice.
- No metaphors, idioms or figurative verbs: not "lands", "lives", "home", "journey", "under the hood", "magic", "spreads", "hides", "watch as".
- No rhetorical questions, no exclamation marks, no "simply", "just", "easily", "powerful", "seamless".
- No parenthetical asides. Make a separate sentence. Parentheses are allowed only to name a term or a value, for example "(vclock)", "(204)", "(w=3)".
- Words used one way only: a copy is a saved object; a vnode is the process that holds copies, always named with its node ("vnode 16 on node2"); a partition is a part of the ring; save, not store; reply, not result or response.
- If the simulator does not do something yet, say so in one sentence.

Error messages name the problem and the accepted values: "There is no node6 in a cluster of 5 nodes."

## Wording and brand

The product name and the links live in `src/lib/brand.ts`. Explainer text is data in `src/lib/explainers.ts`, and says "Dynamo paper" or "DynamoDB" precisely: they are different systems.

## Review

At the end of each phase, take screenshots at desktop and phone widths, in light and dark, and check them against this file, both lists of bans included.
